The hardest part of learning to code isn't the code. It's deciding what to learn first without drowning in a hundred conflicting opinions.

## Skip the "which language" debate

For a first language, pick one of: **Python** (readable, huge community, great for beginners) or **JavaScript** (runs in every browser, useful immediately). Either is fine. The language matters far less than people online make it sound.

## Build, don't just watch

Tutorials feel productive but teach recognition, not recall. You'll understand a video perfectly and then freeze on a blank file. Fix this by pairing every lesson with a tiny project — even something as small as a script that renames files in a folder.

## A realistic four-week starting plan

- **Week 1:** Variables, loops, conditionals. Build a simple calculator.
- **Week 2:** Functions and lists/arrays. Build a to-do list that runs in the terminal.
- **Week 3:** Working with files or an API. Build something that reads a CSV or fetches data from a free API.
- **Week 4:** Put it together. Build one small project end-to-end, even if it's ugly.

## The part nobody tells you

You will feel behind the entire time. Every experienced developer still googles basic syntax. The skill that actually compounds isn't memorization — it's comfort with being confused and debugging your way out of it.
